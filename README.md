# UZEX Deal Analyst — AI-агент по реестру биржевых сделок

Веб-сервис и Telegram-бот, которые отвечают на вопросы о сделках товарно-сырьевой биржи на **русском и узбекском**
(латиница и кириллица). Каждая цифра в ответе — результат SQL-запроса к реестру; под ответом видно, какие запросы
выполнены и что они вернули. Если ответа в данных нет — агент говорит об этом прямо.

## Архитектура

```
вопрос (RU/UZ) ──► Claude (tool use) ──► search_entities  (нечёткий поиск компаний/брокеров/товаров, кир↔лат)
                        │          └──► run_sql          (DuckDB, только чтение, 1 SELECT, таймаут 20 с)
                        ▼
          ответ + «Как посчитано»: SQL, таблицы результатов, время
```

**1. Слой нормализации данных (`build_db.py`)** — главное отличие. Продавцы заполняют карточки по-разному, и наивный
`WHERE name = ...` даёт неверные суммы:
- 230 написаний товаров → **41 каноническое семейство** с узбекскими названиями
  («Хлопок-сырец» = «ХЛОПОК СЫРЕЦ (СПОТ)» = «Хлопок сырец (спот)»; «Масло хлопковое» = «Хлопковое масло»);
- сорт в 9 вариантах («I сорт», «1-сорта», «первый сорт», «в/с», «высшего сорта») → `1/2/3/высший`; класс → `1–4`;
- марка нормализована («ЦЕМ I 42,5 Н» = «ЦЕМI42,5Н») и извлекается из названия, если поле пустое;
- вычисляемые поля: объём = Количество×Лот, цена за единицу, сумма в сумах (экспорт в USD × курс на дату сделки),
  сумма в USD, флаг «сделка состоялась» (не аннулирована).

**2. Агент (`app/agent.py`)** — Claude (Anthropic) с двумя инструментами. Правила в системном промпте: каждая цифра —
только из результата запроса; аннулированные сделки по умолчанию не учитываются; UZS и USD не складываются;
тонны и килограммы не смешиваются; средняя цена — средневзвешенная; в конце ответа — база расчёта.

**3. Интерфейсы** — FastAPI + SSE (потоковый ответ), одностраничный UI RU/UZ с прозрачной трассировкой;
Telegram-бот на том же агенте (`app/tgbot.py`). Защита: SQL только на чтение (запрет DDL/DML/чтения файлов),
лимит запросов на IP/чат.

## Лингвистика

- Понимает русский, узбекский на латинице (старая запись с oʻ/gʻ, любые апострофы или вообще без них),
  узбекский на кириллице, **новый алфавит 2026 года** (Ş, Ç, Ö, Ğ, закон от 21.10.2026), русский латиницей
  («skolko sdelok») и опечатки («скока… без анулированых»). Нечёткий поиск по товарам и компаниям работает
  по транслитерации, поэтому «пахта», «paxta», «xomaşyosi», «hlopok» ведут к одному товару.
- Отвечает той же письменностью, что и вопрос. Узбекская латиница идёт в действующей официальной норме
  (закон о новом алфавите вступает в силу 22.04.2027), с правильными знаками ʻ (U+02BB) и ʼ (U+02BC).
- Словарь биржевой терминологии RU→UZ (bitim, sotuvchi, xaridor, bekor qilingan, ijro etilgan, oʻrtacha tortilgan
  narx…) и узбекские нормы записи чисел и дат («21 321 ta bitim», «2026-yil 30-oktabr», «12,77 trln soʻm»).
- Детерминированная корректура узбекской кириллицы: латинские буквы внутри кириллических слов, ҳ/х
  («Ҳажм», «ҳудуд», «ҳисоб»).

## Проверка точности

`eval/run_eval.py` — 19 вопросов RU/UZ (включая опечатки, кириллицу, новый алфавит) с эталонными ответами, посчитанными SQL вручную, включая 4 «ловушки»
без ответа в данных (прогноз цены, золото, телефон покупателя, 2021 год). Результат: **19/19**, среднее время ~6 с.
Пример: на «средняя цена АИ-92 за литр» агент сам заметил, что часть сделок по бензину продана в тоннах, и не стал
смешивать единицы.

## Запуск

```bash
uv venv && uv pip install -r requirements.txt
python build_db.py data_raw/uzex_spot_data app/uzex.duckdb
echo 'ANTHROPIC_API_KEY=...' > .env   # опционально TELEGRAM_BOT_TOKEN=...
cd app && uvicorn server:app --port 8080
```
Деплой: `fly deploy` (Dockerfile, fly.toml).
